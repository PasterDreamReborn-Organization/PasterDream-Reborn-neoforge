## 3. 来源约定

**直接迁移来源：Forge 重生版当前实现。** 使用兄弟仓库的 `src/main/java`、`src/main/resources`、datagen Provider、规范与设计文档；以记录的提交为起点。后续批次记录实际来源提交，避免源仓库继续演进导致漏搬。

**`NOT_MODIFY/` 是 MCR 原作档案，不属于搬运对象。** 本仓库不创建、不复制、不查阅、不维护该目录，也不维护 ID 映射表。Forge 仓库中的 `NOT_MODIFY/reference`、`reference-resources`、`old-recipes` 属于原作档案，与本项目的 NeoForge 迁移无关。

**目标产物：NeoForge 自己维护。** 代码适配后进入本仓库；生成资源通过本仓库 Provider 重新生成。Forge 的生成 JSON 用于结果对照，不直接作为 NeoForge 的最终生成结果。

本机可通过 `../PasterDream-Reborn-forge1.20.1/` 访问来源；这只是开发参考布局，**不能写成 Gradle、CI 或运行时必需的绝对路径或兄弟目录依赖**。其他开发者可以使用独立的来源仓库 checkout。

## 6. 已核查的技术文档修正点

1. **网络规模**：旧总纲和 `ModNetwork` 注释的 28 个包已过时。当前来源 `init/ModNetwork.java` 有 48 次 `CHANNEL.registerMessage`，包含调试操作与箱子冷却同步等后续内容。
2. **方块实体存取签名**：总纲“BlockEntity / Entity API 未变”的概括不成立。本地 `build/moddev/artifacts/neoforge-21.1.249-sources.jar` 中，`BlockEntity.loadAdditional` / `saveAdditional` 均带 `HolderLookup.Provider`；实体方法需分别核对。
3. **Attachment 同步以锁定依赖源码为准**：官方 1.21.1 文档目前仍描述手写同步包，但本地 **21.1.249** 的 `AttachmentType.Builder` 确有 `sync(AttachmentSyncHandler)`、`sync(StreamCodec)` 等重载。因此不能因旧文档缺少该 API 就删掉现有路线，也不能默认任何 21.1.x 小版本都支持。使用自动同步时仍需验证可变数据更新、登录、重生和换维度行为。见 [官方 Attachment 文档](https://docs.neoforged.net/docs/1.21.1/datastorage/attachments/)。
4. **数据目录不可原样照搬**：1.21 改名包括 `structures → structure`、`recipes → recipe`、`loot_tables → loot_table`、`advancements → advancement`，以及 `tags/items → tags/item`、`tags/blocks → tags/block` 等。总纲中 Curios 的 `tags/items`“原样”建议需修正。`worldgen/structure_set`、`worldgen/template_pool` 在来源数据中本已是单数，不能误作统一“去复数”迁移。见 [Minecraft 1.21 官方更新说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21)。

这里仅列本次确认的问题，未完成对全部 API 示例的逐行校验。后续还需按固定版本核查物品 DataComponents、配方 codec、附魔/画数据驱动、渲染、Curios、Mixin 与存档兼容。
