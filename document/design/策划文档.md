# 策划文档

> PasterDream: Reborn —— 源模组重置项目策划

---

## 一、项目背景

**PasterDream: Reborn** 是对旧版 PasterDream 模组的重置项目。源模组在早期开发中存在诸多不规范问题，本次重置的目标是在保留核心玩法与美术风格的前提下，对代码架构、注册体系、命名规范进行全面整改。

---

## 二、源模组不规范问题总览(待补充)

| 类别 | 问题描述                                            | 重置对策 |
|------|-------------------------------------------------|---------|
| **注册 ID** | 部分方块/物品 ID 无意义（如 `grass_` + 数字后缀）或不符合作者命名习惯     | 沿用 Forge 来源已确定的注册 ID；新增内容按命名规范注册 |
| **客制化类** | 部分方块/物品使用了不必要的客制化类（仅为了满足简单功能而创建独立类）             | 评估必要性：无特殊机制的方块/物品改用原版或通用类 |
| **配方名称** | 配方文件名无意义（`crafting_0.json`、`crafting_1.json` 等） | 见 [命名规范文档](./命名规范文档.md) |
| **材质命名** | 大部分材质文件使用中文拼音命名，与注册 ID 不匹配                      | 见 [命名规范文档](./命名规范文档.md) |
| **MapColor** | 源模组大多数方块未设置 `mapColor`，导致地图上显示颜色不正确               | 注册方块时**必须**设置 `.mapColor()` |
| **方块标签** | 源模组大量方块缺少挖掘工具标签（`MINEABLE_WITH_*`）、材质标签等，导致挖掘速度异常或与其他模组不兼容 | 搬运时**必须**补全标签：挖掘工具、材质、功能标签 |
| **包结构** | 源模组包结构扁平化，所有类集中在少数包中                            | 按功能模块分包（详见 [架构规范](../rule/program/架构规范.md)） |

## 三、ID 命名规范

### 3.1 命名规则

- **全部小写**，单词用下划线分隔（snake_case）
- **语义化**：名称应反映物品/方块的用途或外观
- **禁止**：中文拼音、无意义数字编号、过长的名称（建议不超过 4 个单词）
- **变体处理**：同系列用后缀区分，如 `cyan_stone_brick_slab`、`cyan_stone_pillar`
- 本仓库不维护 ID 映射表；搬运时保留 Forge 重生版已有 ID，新增内容按上述规则直接注册

## 四、客制化类的处理原则

### 4.1 评估标准

在搬运方块/物品时，判断源模组中是否有不必要的客制化类：

| 是否需要客制化类 | 判定条件 | 示例 |
|----------------|---------|------|
| ❌ **不需要** | 方块仅使用原版属性（硬度、爆炸抗性、音效），无特殊交互逻辑 | 普通建筑方块：`CyanStoneBlock` |
| ❌ **不需要** | 物品没有任何右键行为、属性变更、或 tick 逻辑 | 普通素材物品：`AmberCandy` |
| ✅ **需要** | 方块有特殊交互（右键打开 GUI、红石信号响应、实体碰撞等） | `DreamCauldronBlock` → `DreamCauldronBlockEntity` |
| ✅ **需要** | 物品有右键行为、耐久系统、属性修饰、tick 逻辑等 | `SquealWaveWandItem` |
| ✅ **需要** | 方块/物品需要自定义模型渲染或动画 | `WindKnightSpawnblock` |

### 4.2 处理流程

1. 检查源模组中方块/物品的实现类
2. 按上表评估是否必要
3. **不需要的情况**：在 `ModBlocks`/`ModItems` 中直接用 `new Block(Properties...)` / `new Item(Properties...)` 注册
4. **需要的情况**：保留客制化类，但进行代码规范化（命名、结构、注释）

## 六、工作流规范

> **来源约定**：直接迁移来源为外部 Forge 重生版仓库的代码、资源和设计。`NOT_MODIFY/` 是 MCR 原作档案，不属于搬运对象，本仓库不创建、不查阅、不维护。

### 6.1 搬运前的准备

1. **明确搬运目标**：列出本次要搬运的方块/物品清单
2. **来源定位**：在 Forge 重生版仓库的 `src/main/java` 与 `src/main/resources` 中找到对应实现
3. **规范性分析**：检查以下各点并记录：
   - ID 是否与 Forge 来源一致？→ 默认保留，不重命名
   - 是否使用了不必要的客制化类？→ 记录处理方式
   - 材质命名是否规范？→ 如需重命名，记录材质映射
   - 配方（如有）命名是否规范？→ 记录配方重命名方案
   - 标签是否完整？→ 记录缺失的挖掘工具、材质、功能标签
4. **编写搬运方案**：简述如何改、如何重写

### 6.2 方块搬运清单流程

以搬运一个方块为例的标准流程：

1. **[注册]** 在 `init/ModBlocks.java` 中注册：
   - 无特殊机制 → 直接用 `new Block(Properties...)`，**必须**设置 `.mapColor()`
   - 有特殊机制 → 创建客制化类，放在 `world/block/` 包下，类内设置 `mapColor`
2. **[物品关联]** 在 `init/ModItems.java` 中注册对应的 `BlockItem`
3. **[数据生成]** 在以下 Provider 中注册（均位于 `datagen/common/`）：
   - `ModBlockStateProvider` → 方块状态 + 模型
   - `ModItemModelsProvider` → 物品模型（block item）
   - `ModBlockLootTablesProvider` → 战利品表
   - `ModBlockTagsProvider` → 方块标签（**必须**检查并补全：挖掘工具、材质类型、功能标签）
4. **[渲染层]** 若方块需要 cutout / translucent 渲染，在 `client/ClientSetRenderLayer.java` 中注册
5. **[语言文件]** 在 `datagen/lang/` 的 `ModEnUsLangProvider` 和 `ModZhCnLangProvider` 中添加
6. **[材质]** 添加纹理文件到 `assets/pasterdream/textures/block/`（按命名规范命名，动画需同步复制 `.mcmeta`）
7. **[创造模式物品栏]** 在 `init/ModCreativeModeTabs.java` 中添加
8. **[配方搬运]** 在 Forge 来源的 `datagen/common/ModRecipesProvider` 中查找对应配方，按需迁入本仓库（可复用 `datagen/util/RecipeHelpers` 中的 API）
9. **[数据生成运行]** `runData` 生成所有数据文件
10. **[客户端测试]** `runClient` 验证：模型显示、纹理正确、动画、发光、中英文名称、合成配方

### 6.3 物品搬运清单流程

1. **[注册]** 在 `init/ModItems.java` 中注册：
   - 无特殊机制 → 直接用 `new Item(Properties...)`
   - 有特殊机制 → 创建客制化类，放在 `world/item/` 包下
2. **[数据生成]** 在以下 Provider 中注册：
   - `datagen/common/ModItemModelsProvider` → 物品模型
   - `datagen/common/ModItemTagsProvider` → 物品标签（**必须**检查并补全）
3. **[语言文件]** 添加中英文
4. **[材质]** 添加纹理（如需要）
5. **[创造模式物品栏]** 添加到物品栏
6. **[配方搬运]** 在 Forge 来源的 `datagen/common/ModRecipesProvider` 中查找对应配方，写入本仓库 Provider
7. **[数据生成运行]** `runData`
8. **[客户端测试]** `runClient` 验证

### 6.4 粒子搬运清单流程

1. **[粒子类型注册]** 在 `init/ModParticleTypes.java` 中用 `DeferredRegister<ParticleType<?>>` 注册 `SimpleParticleType`
2. **[粒子行为类]** 在 `client/particle/` 下创建粒子类，继承 `TextureSheetParticle`，实现重力、寿命、自旋等物理行为
3. **[粒子提供者]** 在 `client/particle/ModParticles.java` 中通过 `@Mod.EventBusSubscriber(Dist.CLIENT)` + `RegisterParticleProvidersEvent` 注册 `ParticleProvider`
4. **[粒子纹理定义]** 在 `assets/pasterdream/particles/` 下创建 JSON，指向 `textures/particle/` 中的 PNG
5. **[群系引用]** 在 `ModBiomes` 中通过 `.ambientParticle(new AmbientParticleSettings(...))` 引用

### 6.5 维度/群系搬运清单流程

1. **[维度类型]** 在 `worldgen/dimension/ModDimensionTypes.java` 中注册 `DimensionType`
2. **[噪声设置]** 在 `worldgen/dimension/ModNoiseSettings.java` 中注册 `NoiseGeneratorSettings`（含噪声路由器、地表规则）
3. **[维度注册]** 在 `worldgen/dimension/ModLevelStems.java` 中注册 `LevelStem`（关联 BiomeSource + ChunkGenerator）
4. **[群系注册]** 在 `worldgen/biome/ModBiomes.java` 中注册 `Biome`（温度、降雨、颜色、生物生成、雕刻器、特征列表）
5. **[特征/地物]** 在 `worldgen/ModConfiguredFeatures.java` 和 `worldgen/ModPlacedFeatures.java` 中注册
6. **[群系修改器]**（可选）在 `worldgen/biome/ModBiomeModifiers.java` 中通过 NeoForge Biome Modifier 批量添加特征
7. **[维度特效]**（可选）在 `worldgen/dimension/` 下创建 `@Mod.EventBusSubscriber(Dist.CLIENT)` 类注册 `DimensionSpecialEffects`
8. **[语言文件]** 在 datagen lang 中添加群系翻译键 `biome.pasterdream.xxx`
9. **[数据生成运行]** `runData`
10. **[客户端测试]** `runClient`，`/execute in pasterdream:xxx run tp @s ~ ~ ~` 进入维度验证
